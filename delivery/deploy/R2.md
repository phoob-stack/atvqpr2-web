# The test title on Cloudflare R2 (assets.atvqpr2.com)

Nothing here has been run against Cloudflare. These are the steps for the
account owner. No credentials are stored anywhere in this repository:
wrangler uses its own login (`npx wrangler login`).

What goes into the bucket is **only our own test titles** (Box Quad and
Orbit: our C compiled to wasm, procedural assets), one tree per title under
its profile's prefix `games/<id>/` (`profiles/<id>.json`). ATV 2 is never uploaded: its module,
generated C, runtime package and anything from the disc are refused by the
pipeline's gate, and again by `upload-r2.mjs` before any upload. On the site,
ATV 2 keeps "Select local game files".

## Layout

```
games/<id>/latest.json                 { format: delivery-latest/1, title, version, manifest, sha256, size }   Cache-Control: no-cache
games/<id>/v/<version>/manifest.json   the catalog of that version (manifest is relative to games/<id>/)     public, max-age=31536000, immutable
games/<id>/v/<version>/<path>          each file (title.wasm, textures/..., meshes/..., config/...)           public, max-age=31536000, immutable
```

Box Quad 1.1.0 was first uploaded at the bucket root (`latest.json`,
`v/1.1.0-c230f2d0b4ba/`). The pipeline makes the same bytes under
`games/boxquad/`; those root objects stay until the owner deletes them (the
site's Box Quad reads the root's `latest.json` only while
`games/boxquad/latest.json` is missing). Moving: `docs/06-deploy-update-rollback.md`.

`<version>` is `<titleVersion>-<12 hex of the manifest content>`: the same
inputs give the same version and bytes. A release uploads `v/<version>/`
first and `latest.json` last. Old versions are never deleted.

## 1. Bucket and domain (once)

1. Create the bucket `atvqpr2-assets` (dashboard, or `npx wrangler r2 bucket create atvqpr2-assets`).
2. R2 > `atvqpr2-assets` > Settings > Custom Domains: add `assets.atvqpr2.com`
   (the zone `atvqpr2.com` is on Cloudflare, so the DNS record is made for you).
   Leave the `r2.dev` public URL off.
3. CORS (the site's pages fetch from another origin):

   ```
   npx wrangler r2 bucket cors set atvqpr2-assets --file deploy/r2-cors.json
   npx wrangler r2 bucket cors list atvqpr2-assets
   ```

   `deploy/r2-cors.json`: GET and HEAD from `https://atvqpr2.com` and
   `https://www.atvqpr2.com`; request headers `Range`, `If-None-Match`,
   `If-Range` (a resumed download sends `Range` + `If-Range`, which makes the
   browser send a preflight); exposed `Content-Range`, `Content-Length`,
   `ETag`, `Accept-Ranges` (the downloader reads them); preflight cached for
   86400 s.

4. Cache rules (zone `atvqpr2.com` > Caching > Cache Rules), in this order:
   - `assets.atvqpr2.com` and URI path contains `/v/` (`games/<id>/v/...`, and the old root `/v/`): **Eligible for
     cache**, Edge TTL **use cache-control header if present** (the objects
     say `public, max-age=31536000, immutable`), Browser TTL **respect origin**.
   - `assets.atvqpr2.com` and URI path ends with `/latest.json`: **Bypass
     cache** (it says `no-cache`; a rollback then takes effect at once).
   - Optional, for CORS behind the cache: a cached response is shared by all
     origins. Both allowed origins get the same answer only if the cache key
     includes the `Origin` header, or if you add a Response Header Transform
     Rule for `assets.atvqpr2.com` that sets `Vary: Origin`. Check with
     `node pipeline/upload-r2.mjs --check` after the first upload (it asks with
     `Origin: https://atvqpr2.com`) and with the browser test below.
5. Leave Cloudflare's compression on if you like: the browser undoes it before
   the downloader sees the bytes; Range answers are never compressed, so
   resume offsets stay right.

## 2. A release

```
node pipeline/build.mjs                       # out/r2, out/r2-upload-plan.json, gate included
node pipeline/upload-r2.mjs --dry-run         # every check, then the commands it would run
node pipeline/upload-r2.mjs                   # the real upload (wrangler, your login)
node pipeline/upload-r2.mjs --check           # read it back: sizes, Cache-Control, Content-Type, CORS
```

Each object is one command:

```
npx wrangler r2 object put atvqpr2-assets/<key> --file out/r2/<key> --cache-control "<cc>" --content-type <type> --remote
```

`upload-r2.mjs` refuses to start if any file changed since the build, if the
plan and `out/r2` differ, if a key is not `games/<id>/latest.json` or `games/<id>/v/<version>/...` (or names an ATV 2 title),
or if the gate fails on `out/r2`.

## 3. Rollback

Point a title's `latest.json` at an older version of it that is still in the bucket:

```
node pipeline/upload-r2.mjs --rollback 1.1.0-c230f2d0b4ba --title boxquad --dry-run
node pipeline/upload-r2.mjs --rollback 1.1.0-c230f2d0b4ba --title boxquad   # reads .../games/boxquad/v/<version>/manifest.json, checks its files are there, puts games/boxquad/latest.json
node pipeline/upload-r2.mjs --rollback 1.1.0-c230f2d0b4ba --title boxquad --from <an out/r2 that has it>
```

Players' browsers pick it up at their next start (`latest.json` is
revalidated every time); files they already have are not fetched again
(OPFS is content-addressed).

## COEP and the CORS fetches

The site sends `Cross-Origin-Embedder-Policy: require-corp` (the ATV 2 game
page needs cross-origin isolation). Under COEP, a cross-origin response is
allowed either with a `Cross-Origin-Resource-Policy` header or when it was
fetched in CORS mode and passed the CORS check. R2 cannot add CORP to its
answers, but it does answer CORS: every request to `assets.atvqpr2.com` is a
`fetch()` with `mode: 'cors'` (the manifest from the page, the files from the
asset worker), so `require-corp` and the R2 bucket work together. Do not load
anything from the bucket with `<img>`, `<script>` or other no-cors requests:
those would be blocked. The site's CSP must allow the host in `connect-src`
(`_headers`: `connect-src ... https://assets.atvqpr2.com`).

## Local stand-in

`server/asset-server.mjs` with `ASSET_BUCKET_DIR=out/r2` serves the tree the
way R2 does (keys at `/`, Cache-Control and Content-Type from the upload
plan, Range, ETag, `deploy/r2-cors.json` for CORS and preflights). The tests
use it on 127.0.0.1; see the README, "Tests".

## Edge caching as deployed (2026-11-04)

Two rules on the atvqpr2.com zone (dashboard; the wrangler login cannot create them):

- **Cache Rule** "assets edge cache": Hostname equals `assets.atvqpr2.com` -> Eligible for cache; Edge TTL: use the
  Cache-Control header if present, bypass cache if not; Browser TTL: respect origin. With the objects' own headers this
  gives versioned files (`games/<id>/v/...`, `public, max-age=31536000, immutable`) a year at the edge, and each
  `games/<id>/latest.json` (`public, max-age=30`) 30 s, so updates and rollbacks reach players within about 30 s.
- **Response Header Transform Rule**: Hostname equals `assets.atvqpr2.com` -> set `Access-Control-Allow-Origin: *`
  and `Access-Control-Expose-Headers: Content-Length, Content-Range, ETag, Accept-Ranges`. Cloudflare's cache ignores
  `Vary: Origin`, and R2 adds CORS headers only to requests that carry an Origin, so a cached copy made for a request
  without one (curl, a crawler) would otherwise lack them and break the site. `*` is safe for public files fetched
  without credentials, and it works under the site's COEP require-corp. The bucket's own CORS policy
  (`r2-cors.json`) stays for preflights.

`upload-r2.mjs --check` accepts `*` or the site origin.

The bucket root's original Box Quad objects (`latest.json`, `v/1.1.0-c230f2d0b4ba/*`) were deleted after the move
to `games/boxquad/`; that version lives on under `games/boxquad/v/1.1.0-c230f2d0b4ba/`.
